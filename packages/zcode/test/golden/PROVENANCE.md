# Golden files: provenance

Every `<fixture>.<opt>.txt` here is the unedited standard output of Ztools' `infodump -<opt> <fixture>`, for `<opt>` in `i` (header), `a` (abbreviations), `o` (objects), `t` (object tree), `d` (dictionary), `m` (story file map) and `g` (grammar). Every `<fixture>.txd.txt.gz` and `<fixture>.txd-n.txt.gz` is the gzipped standard output of `txd <fixture>` and `txd -n <fixture>`. `test/golden.test.ts` and `test/txd.test.ts` require our formatters to reproduce each one byte for byte, with two exceptions:
- **PunyInform's `txd` files** are compared by structure. Each routine `txd` finished is compared without `txd`'s grammar notes, which come from its misreading of version-3 grammar. The string section is compared exactly, but only where `txd` reached it, which isn't the case for the two v3 stories where it stops partway.
- **`minimal`'s map** isn't compared (see `golden.test.ts`).

**Licensing.** Ztools carries no license, so it is not in this repository in any form: no source, no binary, no WebAssembly build. These files are its output for our own story files (built from Christopher Schweda's sources in `test/fixtures/src`), which is ours to commit. See `docs/00-master-design.md` §11.

**Fixtures.** The stories are compiled by `scripts/build-fixtures.mjs` with `@frotzinc/inform6-wasm` (Inform 6.44, Standard Library 6.12.8, PunyInform), each with `Serial "000000";` injected, so they are byte-for-byte reproducible and these files stay valid. If a fixture's source or the compiler changes, run `scripts/golden.sh` again (it rebuilds every fixture and clears the old golden files first) and commit the result.

**PunyInform** stories have no `-m`/`-g` files: infodump reads their version-3 grammar as version 1 and stops. Their txd files are kept; two v3 ones end partway, where txd stopped.

**Two infodump quirks** the script works around:
- The Unix makefile leaves out Ztools' own `getopt.c`; build with the command above.
- `infodump` formats each line in an 80-byte stack buffer, so a long story path (its first line is `Story file is <path>`) overflows it and it dies silently. The script runs it from the fixtures' folder with bare filenames.
