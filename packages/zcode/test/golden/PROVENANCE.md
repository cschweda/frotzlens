# Golden files: provenance

Every `<fixture>.<opt>.txt` here is the unedited standard output of Ztools' `infodump -<opt> <fixture>`, for `<opt>` in `i` (header), `a` (abbreviations), `o` (objects), `t` (object tree) and `d` (dictionary). `test/golden.test.ts` requires our formatters to reproduce each one byte for byte.

| | |
|---|---|
| Tool | `infodump` 7/3 ("INFODUMP version 7/3"), from Ztools 7/3.1a |
| Archive | `ztools731a.zip`, the 2024 modern-C update, from the IF Archive (`if-archive/infocom/tools/ztools/`) |
| Archive SHA-256 | `3f41e26675687a7abcdf59e3039d5855b5e745c34d98b145b39144960a75a730` |
| Built with | Apple clang 21.0.0, macOS: `cc -O2 -o infodump infodump.c showhead.c showdict.c showobj.c showverb.c txio.c infinfo.c symbols.c getopt.c` |
| Generated by | `scripts/golden.sh <path-to-infodump>`, run from `packages/zcode` |
| Date | 2026-11-06 |

**Licensing.** Ztools carries no license, so it is not in this repository in any form: no source, no binary, no WebAssembly build. These files are its output for our own story files (built from Christopher Schweda's sources in `test/fixtures/src`), which is ours to commit. See `docs/00-master-design.md` §11.

**Fixtures.** The stories are compiled by `scripts/build-fixtures.mjs` with `@frotzinc/inform6-wasm` (Inform 6.44, Standard Library 6.12.8, PunyInform), each with `Serial "000000";` injected, so they are byte-for-byte reproducible and these files stay valid. If a fixture's source or the compiler changes, run `scripts/golden.sh` again and commit the result.

**Two infodump quirks** the script works around:
- The Unix makefile leaves out Ztools' own `getopt.c`; build with the command above.
- `infodump` formats each line in an 80-byte stack buffer, so a long story path (its first line is `Story file is <path>`) overflows it and it dies silently. The script runs it from the fixtures' folder with bare filenames.
